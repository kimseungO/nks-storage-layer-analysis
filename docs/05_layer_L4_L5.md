# 05. L4 / L5 — 중첩 가상화와 K8s CSI 계층

## 목적

NKS와 구조적으로 동일한 지점까지 스택을 쌓아 올립니다.

- **L4**: OpenStack 인스턴스에서 측정하여 중첩 가상화 계층의 비용을 분리합니다.
- **L5**: 동일한 인스턴스 위의 K8s Pod에서 측정하여 CSI와 컨테이너 계층의 비용을 분리합니다.

L5는 NKS(L6)와 거의 동일한 형태의 워크로드로 가정학고, 두 값의 비교가 이 프로젝트의 결론으로 이어집니다.

---

## 1. 실험 구성

### 측정 대상

```
L3 : ubuntu01(KVM 게스트) → Ceph RBD + ext4
                 ↑ 여기까지가 1단계 가상화

L4 : ubuntu01 → OpenStack 인스턴스(k8s-worker1) → Cinder 볼륨 + ext4
                        ↑ virtio가 한 번 더 (중첩 가상화)

L5 : 동일 인스턴스 → K8s Pod → PVC + ext4
                        ↑ CSI + 컨테이너
```

### 변인 통제

**L4와 L5는 동일한 VM에서 측정했습니다.** K8s Pod는 `nodeSelector`로 해당 노드에 고정 배치하여, 두 계층의 차이가 K8s 계층에만 기인하도록 설계했습니다.

```yaml
spec:
  nodeSelector:
    kubernetes.io/hostname: k8s-worker1
```

**L3와 L4의 VM 스펙을 통일했습니다.** k8s-worker1을 4 vCPU / 12GB로 리사이즈하여 ubuntu01과 동일하게 맞췄습니다. 스펙 차이가 남아 있으면 중첩 가상화 비용에 CPU 성능 차이가 섞일 수 있기 때문입니다.

### 볼륨 구성

| 계층 | 볼륨 | 마운트 |
|:----:|------|--------|
| L4 | Cinder 볼륨 60GB (`openstack server add volume`) | `/mnt/rbd-l4` (ext4) |
| L5 | PVC 60Gi (`cinder-rbd` StorageClass) | `/data` (Pod 내부) |

두 볼륨 모두 Cinder를 거쳐 Ceph RBD로 프로비저닝되므로 백엔드 경로가 동일합니다.

L5는 `kubectl exec`으로 Pod 내부에서 실행했습니다. 두 경우 모두 `ljishen/fio` 동일 이미지를 사용했습니다.

## 3. L4 분석 — 중첩 가상화

### 3-1. 동일한 virtio 계층이 다른 손실률을 보입니다

L0 → L1에서 virtio는 randwrite 성능의 53.6%를 소모했으나, L3 → L4에서는 4.1%에 그쳤습니다. 동일한 계층이 추가되었음에도 결과가 크게 다릅니다.

```
L0 → L1
  L0 요청당 시간 :   1.82 µs
  L1 요청당 시간 :   3.92 µs
  → 차이 약 2.1 µs  (기준값의 115%)

L3 → L4
  L3 요청당 시간 : 112.2 µs
  L4 요청당 시간 : 117.0 µs
  → 차이 약 4.8 µs  (기준값의 4%)
```

두 구간에서 추가된 시간의 절대값은 2~5µs로 유사한 수준인 반면, 기준값이 약 60배 차이납니다. 이로 미루어 **virtio가 부과하는 비용 자체는 비슷하나, 하위 계층의 성능 수준에 따라 상대적 영향이 달라지는 것으로 판단됩니다.**

```
L0 단계 : 하드웨어가 매우 빠름 → virtio 비용이 상대적으로 큼
L3 단계 : Ceph가 이미 112µs 소모 → virtio 비용이 묻힘
```

> **병목이 이미 다른 계층에 있으면 추가되는 계층의 비용은 상대적으로 흡수되는 것으로 보입니다.**

### 3-2. seqread에서만 큰 손실이 관측되었습니다

randwrite가 4.1% 손실인 반면 seqread는 34.2% 손실입니다. 워크로드에 따라 다른 요인이 작용하는 것으로 생각됩니다.

| 종목 | 초당 전송량 | L3→L4 손실 | 추정 지배 요인 |
|------|:----------:|:----------:|---------------|
| randwrite 4K | 35 MB/s | 4.1% | 요청당 고정비용 |
| seqwrite 1M | 424 MB/s | 0.7% | Ceph 복제 (이미 포화) |
| randread 4K | 102 MB/s | 20.4% | 요청당 고정비용 |
| **seqread 1M** | **2,094 MB/s** | **34.2%** | **데이터 전송량** |

읽기는 복제가 없어 Ceph 부담이 상대적으로 작습니다. 대신 초당 2GB 규모의 데이터를 게스트 메모리로 전달해야 하므로, 가상화 계층이 하나 더 추가되면서 발생하는 메모리 복사 비용이 그대로 드러난 것으로 보입니다.

```
randwrite : 초당   35 MB 전송 → 전송량 부담 미미
seqread   : 초당 2,094 MB 전송 → 전송량 부담 큼
```

### 3-3. 쓰기 증폭에는 변화가 없습니다

| 종목 | fio | 물리 3개 합계 | 비율 |
|------|:---:|:------------:|:----:|
| randwrite | 35 MB/s | ~290 MB/s | 8.3x |
| seqwrite | 424 MB/s | ~1,150 MB/s | 2.7x |
| randread | 84.8 MB/s | ~87 MB/s | 1.0x |
| seqread | 1,445 MB/s | ~1,450 MB/s | 1.0x |

L2/L3와 동일한 수준입니다. 증폭은 Ceph 계층에서 발생하며, 상위 계층은 이에 영향을 주지 않는 것으로 확인됩니다.

## 4. L5 분석 — Kubernetes 계층

### 4-1. 유의미한 오버헤드가 관측되지 않았습니다

| 종목 | L4 | L5 | 차이 |
|------|:--:|:--:|:----:|
| randwrite 4K | 8,548 | 8,447 | -1.2% |
| randread 4K | 20,700 | 21,300 | +2.9% |
| seqwrite 1M | 404 | 400 | -1.0% |
| seqread 1M | 1,378 | 1,391 | +0.9% |

모두 1% 내외이며, 일부 종목은 오히려 L5가 높게 측정되었습니다. 실행 시점에 따른 편차 범위로 판단되며, **K8s 계층의 오버헤드는 측정 오차와 구분되지 않는 수준으로 보입니다.**

### 4-2. 구조적 배경

**컨테이너는 가상화가 아닙니다.**

```
VM         : 게스트 커널 → virtio → 호스트 커널 → 디스크
컨테이너   : 호스트 커널 → 디스크
             ↑ namespace/cgroup 격리이며 커널을 공유
```

Pod 내부의 fio가 `/data/testfile`에 쓸 때, bind mount를 통해 노드의 ext4로 전달됩니다. 추가적인 변환 계층이 개입하지 않는 것으로 보입니다.

> **주의:** 컨테이너 이미지 레이어(`/tmp` 등)에 쓰는 경우 overlayfs를 거치므로 오버헤드가 발생할 수 있습니다. PVC 마운트 경로는 bind mount이므로 이에 해당하지 않습니다.

### 4-3. 실무적 함의

> **"K8s나 컨테이너 때문에 스토리지가 느리다"는 통념은 이번 측정 결과와 부합하지 않습니다.**
> 본 환경에서 K8s CSI와 컨테이너 계층의 오버헤드는 1% 이내로, 측정 오차와 구분되지 않았습니다.

MSP 환경에서 "K8s로 전환한 후 느려졌다"는 문의를 받았을 때, 원인 후보에서 K8s 계층의 우선순위를 낮추고 백엔드 스토리지와 볼륨 정책을 먼저 확인하는 것이 효율적일 것으로 판단됩니다.

다만 이 결론은 **본 측정 환경(Cinder CSI, ext4, 단일 노드 배치)에 한정**됩니다.

## 6. 결론

| 항목 | 결과 |
|------|------|
| 중첩 가상화 비용 (randwrite) | 4.1% — 하위 계층 병목에 흡수된 것으로 보임 |
| 중첩 가상화 비용 (seqread) | **34.2%** — 데이터 전송량 부담으로 추정 |
| K8s CSI + 컨테이너 비용 | **1% 이내 (측정 오차 수준)** |
| 쓰기 증폭 | Ceph 계층과 동일, 변화 없음 |

> **중첩 가상화의 비용은 워크로드 유형에 따라 4%에서 34%까지 다르게 관측되었습니다.**
> 요청 수가 많은 4K 랜덤에서는 Ceph 병목에 흡수되는 반면, 전송량이 큰 1M 순차 읽기에서는 손실이 두드러졌습니다. 이는 가상화 계층이 요청당 고정비용과 데이터 전송 비용을 각각 부과하며, 워크로드에 따라 지배적 요인이 달라지기 때문으로 생각됩니다.
>
> **K8s 계층은 성능에 유의미한 영향을 주지 않는 것으로 확인되었습니다.** CSI가 데이터 경로에 개입하지 않고, 컨테이너가 커널을 공유하는 격리 방식이라는 구조적 특성에서 비롯된 것으로 보입니다.

L5는 NKS(L6)와 동일한 형태의 측정 지점입니다. 다음 문서에서 두 값을 대조하여 NKS 수치의 성격을 검토합니다.
