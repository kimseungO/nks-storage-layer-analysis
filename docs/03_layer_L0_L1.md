# 03. L0 / L1 — 물리 NVMe 기준선과 KVM 가상화 비용

## 목적

측정 스택의 최하단 두 계층을 분석합니다.

- **L0**: 물리 NVMe의 성능 상한을 확보하여 이후 모든 계층의 기준선으로 삼습니다.
- **L1**: 동일한 물리 파티션을 KVM 게스트에 패스스루하여, virtio 계층이 부과하는 비용을 분리합니다.

---

## 1. 실험 구성

### 측정 대상

```
L0 : 호스트 → /dev/nvme*p6 (49.4GB 파티션, raw)

L1 : 호스트 → KVM(ubuntu01) → /dev/vdd (동일 파티션, raw)
                  ↑ virtio-blk 패스스루
```

동일한 물리 영역을 사용하므로 **변인은 'KVM 가상화'입니다.**

### 파티션 연결

```bash
virsh attach-disk vm-2 /dev/nvme0n1p6 vdc \
  --driver qemu --subdriver raw --cache none \
  --targetbus virtio --live
```

`--cache none` 옵션이 중요합니다. 호스트 페이지 캐시를 우회해야 게스트의 `direct=1`이 실제 물리 디스크까지 도달합니다. 이 옵션이 없으면 호스트 RAM 성능을 측정하게 될 수 있습니다.

### 사전 조치

| 항목 | 조치 |
|------|------|
| 프리컨디셔닝 | 전체 영역 순차 쓰기 2회 |
| 워킹셋 | `offset_increment=2G` (4잡 × 2GB = 8GB) |
| 관측 | 호스트에서 `iostat -x 1` 동시 수집 |

---

## 2. 측정 결과

### L0 — 물리 NVMe 기준선

| 종목 | IOPS | Bandwidth | 평균 lat | p99 | p99.99 |
|------|:----:|:---------:|:--------:|:---:|:------:|
| randwrite 4K | **550,000** | 2,147 MiB/s | 232 µs | 955 µs | 11.3 ms |
| randread 4K | **559,000** | 2,183 MiB/s | 229 µs | 783 µs | 1.4 ms |
| seqwrite 1M | 4,966 | **4,967 MiB/s** | 3.22 ms | 8.85 ms | — |
| seqread 1M | 6,608 | **6,609 MiB/s** | 2.42 ms | 2.97 ms | — |

WD_BLACK SN850X의 본 측정 조건에서의 성능 상한입니다. 읽기와 쓰기가 거의 동일하게 나타났는데(550k vs 559k), NVMe는 내부 병렬 채널이 많아 이 정도 부하에서는 방향에 따른 차이가 크지 않은 것으로 보입니다.

### L1 — KVM 게스트

| 종목 | IOPS | Bandwidth | 평균 lat |
|------|:----:|:---------:|:--------:|
| randwrite 4K | **255,000** | 996 MiB/s | 501 µs |
| randread 4K | **310,000** | 1,211 MiB/s | 412 µs |
| seqwrite 1M | 5,214 | **5,214 MiB/s** | 3.07 ms |
| seqread 1M | 6,592 | **6,592 MiB/s** | 2.43 ms |

### 비교

| 종목 | L0 | L1 | 잔존율 |
|------|:--:|:--:|:------:|
| randwrite 4K | 550,000 | 255,000 | **46.4%** |
| randread 4K | 559,000 | 310,000 | **55.5%** |
| seqwrite 1M | 4,967 | 5,214 | **105.0%** |
| seqread 1M | 6,609 | 6,592 | **99.7%** |

**랜덤 4K에서는 약 절반이 소실되고, 순차 1M에서는 유의미한 손실이 관측되지 않았습니다.**

---

## 3. 분석

### 3-1. virtio가 요청당 고정 비용을 부과하는 것으로 보입니다

virtio-blk의 I/O 처리 경로는 일반적으로 다음과 같이 알려져 있습니다.

```
게스트 애플리케이션
  → 게스트 커널 블록 레이어
  → virtio 링 버퍼에 요청 삽입
  → VM exit (게스트 → 호스트 전환)
  → 호스트 QEMU I/O 스레드가 처리
  → 물리 디스크 제출
  → 완료 인터럽트 주입
  → 게스트로 복귀
```

이 왕복에 소요되는 시간은 **요청의 크기와 무관하게 일정할 것으로 예상됩니다.**

### 3-2. 4K에서만 손실이 드러난 이유

요청당 처리 시간으로 환산하면 다음과 같이 설명할 수 있습니다.

```
randwrite 4K
  L0 요청당 시간 : 1초 ÷ 550,000 =  1.82 µs
  L1 요청당 시간 : 1초 ÷ 255,000 =  3.92 µs
  → 차이 약 2.1 µs (원래 시간의 115%)

seqwrite 1M
  L0 요청당 시간 : 1초 ÷ 4,967 = 201.3 µs
  L1 요청당 시간 : 1초 ÷ 5,214 = 191.8 µs
  → 차이가 전체의 1% 미만
```

4K 테스트는 초당 약 55만 회, 1M 테스트는 초당 약 5천 회의 요청을 발생시킵니다. **요청 횟수가 약 110배 차이나므로 고정 비용의 상대적 비중이 크게 달라지는 것으로 판단됩니다.**

### 3-3. seqwrite가 소폭 상승한 이유

L1의 seqwrite가 L0보다 약 5% 높게 측정되었습니다. 5%는 측정 편차 범위로도 볼 수 있으므로 **"유의미한 손실 없음"으로 해석할 수 있습니다.**

## 4. 물리 계층 교차 검증

### fio ↔ iostat 1:1 대응

| 종목 | fio 보고 | 호스트 iostat | 비율 |
|------|:--------:|:-------------:|:----:|
| L0 randwrite | 2,251 MB/s | ~2,250 MB/s | 1.00 |
| L0 seqwrite | 5,208 MB/s | ~5,100 MB/s | 0.98 |
| L0 seqread | 6,930 MB/s | ~6,790 MB/s | 0.98 |
| L1 randwrite | 1,045 MB/s | ~1,110 MB/s | 1.06 |
| L1 seqwrite | 5,468 MB/s | ~5,350 MB/s | 0.98 |
| L1 seqread | 6,912 MB/s | ~6,780 MB/s | 0.98 |

**증폭이 관측되지 않았습니다.** 클라이언트가 요청한 만큼 물리 디스크에 기록된 것으로 보입니다. 이 값을 이후 계층에서 비교할 기준선으로 삼았습니다.

### 요청 크기 일치

| 종목 | L0 `wareq-sz` | L1 `wareq-sz` |
|------|:-------------:|:-------------:|
| randwrite 4K | 4.00 KB | 4.00 KB |
| seqwrite 1M | 128.00 KB | 128.00 KB |
| seqread 1M | 128.00 KB | 128.00 KB |

1M 요청이 물리 계층에서 128KB로 분할되는데, 커널 블록 레이어의 `max_sectors_kb` 기본값(128KB)에 따른 것으로 보입니다. **L0와 L1이 동일한 값을 보이므로 virtio가 요청 크기를 변경하지는 않는 것으로 판단됩니다.**

### 물리 디스크 처리 시간의 변화

가장 주목한 관측입니다.

| 종목 | L0 `w_await` | L1 `w_await` |
|------|:------------:|:------------:|
| randwrite 4K | 0.05 ~ 0.16 ms | 0.09 ~ 0.12 ms |

```
물리 디스크가 요청 하나를 처리한 시간 : 유의미한 변화 없음
게스트가 체감한 지연 시간             : 232 µs → 501 µs (약 2.2배)
```

**지연 증가가 물리 디스크가 아니라 virtio 계층에서 발생했을 가능성이 높다고 판단됩니다.** 

호스트 CPU `%iowait`가 L0의 25~35%에서 L1의 45~52%로 상승했습니다. 동일한 물리 I/O를 처리하는데 CPU 대기가 늘어난 것으로, virtio 처리에 추가 CPU가 소모되는 것으로 보입니다.

## 5. Little's Law 검증

`Latency = Queue Depth / Throughput`

| 계층 | 종목 | 예측값 | 실측값 | 오차 |
|------|------|:------:|:------:|:----:|
| L0 | randwrite | 128 ÷ 550,000 = 232.7 µs | 232.47 µs | 0.1% |
| L0 | randread | 128 ÷ 559,000 = 229.0 µs | 228.77 µs | 0.1% |
| L0 | seqwrite | 16 ÷ 4,966 = 3,221 µs | 3,220.78 µs | 0.01% |
| L0 | seqread | 16 ÷ 6,608 = 2,421 µs | 2,420.09 µs | 0.04% |
| L1 | randwrite | 128 ÷ 255,000 = 502 µs | 501.17 µs | 0.2% |
| L1 | randread | 128 ÷ 310,000 = 413 µs | 411.80 µs | 0.3% |
| L1 | seqwrite | 16 ÷ 5,214 = 3,068 µs | 3,067.91 µs | 0.003% |
| L1 | seqread | 16 ÷ 6,592 = 2,427 µs | 2,426.46 µs | 0.02% |

전 종목에서 오차 0.3% 이내로 일치했습니다. 측정 구간에 큰 외부 노이즈가 없었음을 보여줍니.

---

## 6. 결론

| 항목 | 결과 |
|------|------|
| 물리 NVMe 상한 | randwrite 550k IOPS / seqread 6,609 MiB/s |
| KVM 가상화 비용 (4K 랜덤) | **약 54% 손실** |
| KVM 가상화 비용 (1M 순차) | **유의미한 손실 없음** |
| 쓰기 증폭 | 관측되지 않음 (1:1) |
| 지연 발생 위치 | virtio 계층으로 추정 (물리 디스크 `w_await` 불변) |

> **KVM 가상화 비용은 데이터 전송량보다 요청 처리 횟수에 비례하는 것으로 보입니다.**
> virtio가 요청당 약 2µs의 고정 비용을 부과하는 것으로 추정되며, 이 값이 요청 자체의 처리 시간(1.82µs)과 비슷한 수준이므로 4K 랜덤에서 성능이 절반 수준으로 감소한 것으로 판단됩니다. 반면 순차 1M에서는 요청당 처리 시간이 201µs이므로 고정 비용이 희석되어 오버헤드가 드러나지 않은 것으로 보입니다.

이 해석은 L3 → L4(중첩 가상화) 구간에서 다시 검토됩니다. 동일한 virtio 계층이 그곳에서는 4%만 소모하는 것으로 관측되는데, 하위 계층(Ceph)이 이미 112µs를 소모하고 있기 때문으로 생각됩니다.
